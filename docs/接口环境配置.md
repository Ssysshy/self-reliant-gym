# 接口环境配置与部署

一个小程序包同时带三套接口地址：默认按微信注入的 `envVersion` 自动选，也可以用 `pnpm run build:dev|test|prod` 手动指定，**发版不用改代码**。

## 一张表看懂

| 环境           | 怎么进                | 接口地址                                                            | 后端跑在哪        | 域名校验                  |
| -------------- | --------------------- | ------------------------------------------------------------------- | ----------------- | ------------------------- |
| 开发 `develop` | 开发者工具 / 真机调试 | `http://127.0.0.1:18080/api/v1` 或 `http://<局域网IP>:18080/api/v1` | 自己电脑 `go run` | 关闭（`urlCheck: false`） |
| 体验 `trial`   | 后台设为体验版后扫码  | `https://api.example.com/api/v1`                                    | 服务器容器        | 开启，必须是已登记域名    |
| 正式 `release` | 审核通过后线上版本    | `https://api.example.com/api/v1`                                    | 服务器容器        | 开启，必须是已登记域名    |

`envVersion` 是微信按版本自动注入的，取值只有 `develop`（开发者工具、真机调试）、`trial`（体验版）、`release`（正式版），不是自己传的。

## 小程序端

### 切环境用命令

```bash
pnpm run build:dev     # 本地开发，http://127.0.0.1:18080/api/v1
pnpm run build:test    # 体验版地址
pnpm run build:prod    # 正式地址
pnpm run build:auto    # 清掉手动选择，回到按版本自动判断
pnpm run env:status    # 只打印当前是哪套，不改文件
```

命令做的是改写 `config/env.js` 里这一行，不产出构建产物（小程序由开发者工具直接编译源码，没有 `dist` 之说）：

```js
const ACTIVE_ENV = ""; // dev | test | prod | 空 = 按版本自动
```

改完开发者工具会自动重编译（没动就手动点一下编译），控制台打印一行确认：

```
[env] 本地开发 (develop) → http://127.0.0.1:18080/api/v1
```

手动选择优先于版本判断，但**正式版不认手动选择**：

| 手动选择     | 开发者工具 / 调试 | 体验版     | 正式版       |
| ------------ | ----------------- | ---------- | ------------ |
| 自动（默认） | 本地              | 体验版地址 | 正式地址     |
| `build:dev`  | 本地              | 本地       | **正式地址** |
| `build:test` | 体验版地址        | 体验版地址 | **正式地址** |
| `build:prod` | 正式地址          | 正式地址   | **正式地址** |

这一处例外是故意的：某次 `build:dev` 之后忘了切回来就发版，线上会指向 `127.0.0.1`，而这种事故不报错、只在用户那里表现为"网络连接失败"，极难定位。

### 地址本身

地址写在 `config/env.js` 的 `PROFILES` 里，命令只是选其中一套：

```js
const PROFILES = {
  develop: {
    apiBase: "http://127.0.0.1:18080/api/v1",
    devLanIp: "", // 真机调试时填开发机局域网 IP，如 "192.168.1.8"
  },
  trial: { apiBase: "https://api.example.com/api/v1" },
  release: { apiBase: "https://api.example.com/api/v1" },
};
```

拿域名之后要改的只有两行（`trial` 和 `release` 的 `apiBase`），`api.example.com` 换成自己的。

解析优先级（`resolve()`）：

1. `wx.getExtConfigSync().apiBase` —— 只有第三方平台代管才有，普通小程序为空
2. 本地缓存 `apiBase` —— **仅非正式版生效**，真机调试临时指到开发机用
3. 手动选择 `ACTIVE_ENV`（`build:dev` 等命令写入）；为空时用 `envVersion` 对应的那套
4. 该套配置有 `devLanIp` 时再叠加（局域网地址替代 `127.0.0.1`）

`app.js` 启动时解析一次写进 `globalData.apiBase`，`api.ts` 只读它。页面里不要出现任何域名。

两条告警：

```
[env] 正式版接口必须是 https，当前是 http://... ，真机上会被微信拦截
[env] 当前连的是本机 http://127.0.0.1:18080/api/v1，只在开发者工具里有效，手机上会连不上
```

### 本地开发

```bash
# 1. 起后端（首次先 cp .env.example .env，见 backend/README）
cd self-reliant-gym-backend/apps/backend && go run ./cmd/api

# 2. 开发者工具导入 self-reliant-gym 目录，编译
#    详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」
```

`project.private.config.json` 里已经是 `"urlCheck": false`，换电脑时要重新勾一次（这个文件不进 git）。

启动时控制台会打印当前环境，确认没连错地方：

```
[env] 本地开发 (develop) → http://127.0.0.1:18080/api/v1
```

### 真机调试

手机上的 `127.0.0.1` 指手机自己，必须让手机连到开发机的局域网 IP：

1. 手机和电脑连同一个 WiFi
2. 查电脑 IP：`ipconfig getifaddr en0`（macOS）
3. 二选一：
   - 把 IP 填进 `config/env.js` 的 `devLanIp`（如 `'192.168.1.8'`，不带 `http://` 和端口）
   - 或在开发者工具 Console 里 `setApiBase('http://192.168.1.8:18080/api/v1')`，然后重新预览
4. 后端必须监听 `0.0.0.0`（`.env` 里 `LISTEN_ADDR=:18080`，默认就是），改成 `127.0.0.1:18080` 手机就连不上
5. 电脑防火墙放行 18080，否则手机请求直接超时

调试完把 `devLanIp` 清空、或执行 `clearApiBase()`，否则模拟器也会去连那个 IP。

### 拿域名之后

小程序只要求 HTTPS，不要求域名在 root 下——所以规划成独立子域 `api.example.com`，后台页面和接口同域也能用。

## 后端

两份环境模板，对应两个场景：

| 文件                      | 用途                             | 关键差异                                                         |
| ------------------------- | -------------------------------- | ---------------------------------------------------------------- |
| `.env.example`            | 本地开发，`cp .env.example .env` | `GYM_LOCAL=1`、`WX_SECRET` 可空、`MYSQL_DSN` 指 `127.0.0.1:3306` |
| `.env.production.example` | 服务器，重命名为 `.env`          | `GYM_LOCAL=0`、`WX_SECRET` 必填、口令全换真值                    |

**最危险的一条**：生产环境把 `GYM_LOCAL` 留成 `1` 且 `WX_SECRET` 为空时，登录会退化成固定测试账号 `local_dev_user`——所有用户都是同一个人。检查清单里第一条就是它。

后端没有"环境开关"，靠的是**两份配置物理分开**：本地机器上是 `.env`（开发），服务器上是 `/opt/gym/.env`（生产），各放各的，互不覆盖。

本地要临时验证生产配置（比如查线上登录问题），用 `ENV_FILE` 指过去，原 `.env` 不动：

```bash
cp .env.production.example .env.production   # 填好真实值，这个名字不进 git
cd apps/backend
ENV_FILE=../../.env.production go run ./cmd/api
```

设了 `ENV_FILE` 就只读那一个文件、不再向上找 `.env`；指错路径会直接退出并报 `ENV_FILE 指定的配置文件读不到`——不会悄悄用开发配置连库，那种错最难查。

改完配置要**重启进程**才生效（`docker compose restart api` 或重新 `go run`），运行中改文件不会热加载。

## 部署

日常流程不变（见 backend/README「一键发布」）：

```bash
./deploy/build.sh                                  # 本机构建 amd64 镜像
./deploy/publish.sh user@1.2.3.4 --config --env .env.production   # 首次（连生产配置一起传）
./deploy/publish.sh user@1.2.3.4                   # 之后
```

`--config` 上传前会校验配置：`GYM_LOCAL=1`、`WX_SECRET` 为空、`SESSION_SECRET` 不足 32 字节、还留着 `__CHANGE_ME` 占位符，任何一条命中都会在**上传之前**退出并说明原因——这几项错了不会报错，只会静默地让线上所有人变成同一个测试用户。

### 有域名之后启用 HTTPS

默认 compose 只把端口绑在 `127.0.0.1:18080`，公网访问不到，只能 SSH 隧道调试：

```bash
ssh -L 18080:127.0.0.1:18080 user@1.2.3.4    # 然后本机访问 http://127.0.0.1:18080
```

要对外提供服务，叠加 `deploy/docker-compose.https.yml`：

```bash
# 1. 改域名：把 deploy/nginx.https.conf 里的 api.example.com 全换成自己的
# 2. 放证书
mkdir -p deploy/certs
#    拷入 fullchain.pem（服务器证书+中间证书）和 privkey.pem
# 3. 起服务
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.https.yml up -d
```

叠加文件只做三件事：暴露 80/443、把 `nginx.https.conf` 换进容器、挂载证书目录。回滚就去掉 `-f deploy/docker-compose.https.yml`。

用 `publish.sh` 发布时不必手敲：首次 `--config` 会检测 `deploy/certs/` 里的证书，凑齐就整套传上去；之后日常发布会检测服务器上的叠加文件并自动追加 `-f`，避免一次普通发布把 443 弄丢。

`deploy/certs/` 和 `deploy/certbot/` 已在 `.gitignore` 里，证书不会进仓库。

证书获取的三种常见方式：

- **云厂商免费证书**（阿里云/腾讯云 DV 证书，1 年）：控制台申请 → 下载 Nginx 格式 → 拷进 `deploy/certs/`
- **certbot**：`certbot certonly --webroot -w deploy/certbot/www -d api.example.com`，签发后把 `/etc/letsencrypt/live/api.example.com/` 下的两个文件软链到 `deploy/certs/`，3 个月需续期
- **CDN / 负载均衡**：证书挂在云产品上，回源 `http://<服务器IP>:18080`，此时不需要叠加 compose，但要把 `nginx.conf` 的端口从 `127.0.0.1:18080:80` 改成 `18080:80` 并配置安全组只放行云厂商回源 IP

## 上线检查清单

### 服务器

- [ ] 域名已备案（服务器在大陆必须，否则 80/443 会被阻断）
- [ ] 域名 A 记录指向服务器公网 IP
- [ ] `curl -I https://api.example.com/api/v1/exercises` 返回 200，且证书链完整（`openssl s_client -connect api.example.com:443 -servername api.example.com </dev/null | grep Verify`）
- [ ] `deploy/certs/` 里是 `fullchain.pem`（含中间证书），只放服务器证书会报「证书链不完整」
- [ ] 服务器 `.env` 用的是 `.env.production.example` 的内容，不是开发机那份

### 生产配置

- [ ] `GYM_LOCAL=0`
- [ ] `WX_SECRET` 已填（微信公众平台 → 开发管理 → 开发设置 → AppSecret）
- [ ] `SESSION_SECRET` 与开发机不同，且 ≥ 32 字节（`openssl rand -base64 48`）
- [ ] `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD` / 后台口令全部换过
- [ ] 后台能登进去改一次密码，确认新口令生效

### 微信公众平台

- [ ] 开发管理 → 开发设置 → **服务器域名 → request 合法域名**：`https://api.example.com`（不带路径、不带端口）
- [ ] 用到上传时补 `uploadFile` / `downloadFile` 域名，同一域名即可
- [ ] 域名必须 HTTPS 且证书有效；每月只能改 5 次，一次填对
- [ ] 上传代码 → 后台设为体验版 → 扫码验证 `trial` 环境能登录

### 小程序端

- [ ] `config/env.js` 里 `trial` / `release` 的 `apiBase` 已换成正式域名
- [ ] `release` 是 `https://`（控制台若无红字告警即为通过）
- [ ] `devLanIp` 已清空
- [ ] 正式版用「不校验合法域名」是关着的状态测一遍（详情 → 本地设置）

## 常见报错对照

| 现象                                  | 原因                                               | 处理                                                       |
| ------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| `request:fail url not in domain list` | 域名没登记，或登记了但版本是正式版仍用 http        | 微信后台加合法域名；确认 `release` 是 https                |
| `request:fail ssl hand shake error`   | 证书链不完整 / 证书过期 / 只有 TLS 1.0             | 换 `fullchain.pem`；nginx 已限 TLS 1.2+                    |
| 真机 `网络连接失败`、模拟器正常       | 手机连的是 `127.0.0.1`，或电脑防火墙挡了           | 填 `devLanIp`；放行 18080                                  |
| 一直转圈然后超时                      | 请求没有超时保护（已加 15s），后端没起或 nginx 502 | 看 `docker compose logs -f api`                            |
| 接口 401                              | token 过期（12 小时）                              | `api.ts` 已自动清 token，重新登录即可                      |
| 体验版报「微信登录失败」，正式版正常  | 体验版配的后端 `WX_SECRET` 不对                    | 检查服务器 `.env`，日志里有 `jscode2session 失败 errcode=` |
| 所有用户看到同一份数据                | 生产 `GYM_LOCAL=1` 且 `WX_SECRET` 为空             | 改 `GYM_LOCAL=0` 并填密钥，重启 api                        |
